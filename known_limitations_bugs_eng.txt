Known Limitations / Bugs
------------------------------
[Array Fields Cannot Be Edited]
  Array fields cannot currently be edited in TableManage.
  A hint appears on double-click or when clicking "Edit".

  Affected:
    - TableManage → Fields → "Edit" on an array field
    - TableManage → Fields → Double-click on an array field

  Background:
    Firebird does not allow changing array dimensions via
    ALTER COLUMN. To modify an array field, it would have to be
    dropped and recreated completely — with all consequences for
    dependent objects (triggers, views, foreign keys).

  A dedicated array editor is planned for a future release.

  Display (read-only) works:
    - TreeView → Fields
    - Extract → Extract Table Fields
    - Extract → Extract Table MetaData
    - TableManage → Fields (column "Field Type")


[CSV Export with Case-Sensitive Tables]
- The CSV export (Bulk Export) currently does not support
  case-sensitive table names. Tables with mixed case
  (created with double quotes) cannot be exported correctly.



[NUMERIC Precision > 16 on FB 4+]
NUMERIC with precision up to 38. However,
IBX 2.7.x has a bug in the BCD conversion for values with
precision > 16. TurboBird works around this by automatically
reducing precision to 16 — values may be truncated.

Bug report submitted to Tony Whyman on <date>.



[Foreign Key Creation on Firebird 1.5]
- On Firebird 1.5, a new Foreign Key cannot be created through TurboBird.
  The server requires exclusive database access for this DDL operation,
  but TurboBird keeps active connections to the database open. The server
  rejects the operation with "object <TABLE> is in use".

  Affected:
    - TableManage → Foreign Keys → "New Foreign Key"

  Workaround:
    Create the Foreign Key with isql or another tool that opens only a
    single connection to the database. Then refresh the Foreign Keys tab
    in TurboBird.

    Example (Linux):
      isql -user SYSDBA -password <pwd> /path/to/db.fdb
      SQL> ALTER TABLE EMPLOYEE ADD CONSTRAINT FK_EMPLOYEE_DEPT
           FOREIGN KEY (DEPT_NO) REFERENCES DEPARTMENT (DEPT_NO);
      SQL> COMMIT;
      SQL> QUIT;

  Note:
    Firebird 2.0 and newer are not affected — there, FK creation
    works as expected.

[Tablelock]
- When a table is opened and the corresponding tab is closed afterwards, 
  the table lock remains active until the database connection is fully closed 
  (e.g., by disconnecting the database or closing the entire application). 
  This may prevent DDL operations such as DROP TABLE or ALTER TABLE on the same table.

  Workaround: Use "Disconnect and Close All Windows" from the database node context menu 
  to release all locks.

[PascalScript Studio]
- When using {$I} include directives or additional units in the uses clause,
  the debugger line numbers are no longer mapped correctly.
  As a result, incorrect lines are highlighted in the editor during step-by-step script execution.
  This is caused by included source files changing the internal line offsets used by the debugger.

[Edit Table Data]
- Case-sensitive table names are currently not supported.

[Embedded Connections]
- The user manager is hidden.
  Login is currently only possible with SYSDBA.

[DB Tools → DB Info → Tab "Pages"]
- The values for "Used Pages" and "Free Pages" are swapped.
- This behavior also occurs in IBX DBAdmin.
  → Likely an IBX issue.

[RTF Export]

- Currently unstable and under active development.

[Sorting with calculated columns without aliases]
- Problem: Attempting to sort a calculated column without an alias (system-generated name like CONCATENATION)
  in the grid leads to SQL error -206 (Column unknown - CONCATENATION).
  This also occurs with multi-column sorting (custom-built), because Firebird does not accept the internal
  column name for ORDER BY.

  Affected query (produces error when sorting):
  SELECT
    '1' || ' = ' || ASCII_VAL('1'),
    '2' || ' = ' || ASCII_VAL('2'),
    ...
    'Z' || ' = ' || ASCII_VAL('Z')
  FROM RDB$DATABASE;

  Workaround: Give each calculated column a unique alias, e.g. AS COL1, AS COL2, …
  After that, sorting works perfectly – both single and multi-column.

  Corrected query (works with sorting):
  SELECT
    '1' || ' = ' || ASCII_VAL('1') AS COL1,
    '2' || ' = ' || ASCII_VAL('2') AS COL2,
    ...
    'Z' || ' = ' || ASCII_VAL('Z') AS COL16
  FROM RDB$DATABASE;

  Affects: Custom-built sorting procedures in QueryWindow.
  Status: May be fixed in a future version.
